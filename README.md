Вход: `data/Sepsis Cases - Event Log.xes.gz`; ожидаемый SHA-256 `709c52340306415952811b9b9c5dc6bcc8f8d47d583eba39df9a538459dc543a`. .venv/Scripts/python.exe -m unittest discover -s tests -v

Для формирования отчёта по сохранённым результатам `outputs/final` выполните `.venv/Scripts/python.exe create_report.py`. Скрипт перезаписывает `report/Отчет_ПР4_Процессная_аналитика.docx`; сохраните свои изменения в другом файле перед его запуском. Зависимость python-docx включена в requirements.txt. Для запуска из другого рабочего каталога укажите абсолютный путь к скрипту; вход по умолчанию всегда ищется относительно расположения скрипта. `--input` задаёт другой XES gzip, `--output` — новый или пустой каталог; существующие непустые каталоги не перезаписываются. `--edge-threshold 400` задаёт частотный порог визуального подграфа.

## Обработка и ограничения

* `trace/concept:name` — ID случая, `event/concept:name` — действие, `event/time:timestamp` — время. Остальные атрибуты и глобальные значения по умолчанию не подставляются и не анализируются. Повтор ID между трассами вызывает ошибку, а не слияние.
* Каждый timestamp с указанной зоной приводится к UTC. Отсутствующие, некорректные или naive timestamps отбрасываются; также отбрасываются события без ID случая или имени действия. Категории исключений взаимно исключают друг друга и применяются по порядку ID → действие → время; пустые после фильтра случаи не входят в анализ. Все счётчики есть в `summary.json/quality`.
* События сортируются по UTC внутри случая; при совпадении времени сохраняется первоначальный порядок файла. Дубликаты не удаляются: даже точные повторы могут быть разными событиями. Подсчёты строятся после сортировки. Совпавшее время не доказывает реальный порядок.
* Длительность — время между первым и последним оставшимися событиями, интервал перехода — между соседними событиями, не обязательно ожидание или рабочее время. При одном событии длительность 0 и нет максимального интервала. P95 — линейная интерполяция в позиции `(n−1)×0.95`; медиана — стандартная медиана. Сумма длительностей переходов не равна времени занятости ресурсов.
* DFG — частоты непосредственно следующих событий, не модель причинности и не доказательство параллельности. `dfg_full.html` показывает полный граф в виде кликабельных списков исходящих стрелок; PNG содержит все узлы, но только рёбра с частотой ≥400 (12 из 115 в этом запуске). Возможны пересечения; полные идентификации и частоты — в HTML/CSV.
* Самопереходы — соседние одинаковые действия. Повтор действия в трассе — два или более появления, не обязательно рядом. Это не обязательно ошибки или нежелательная работа.
* Многозвенные циклы ограничены двумя различными действиями: `graph_two_node_cycles.csv` содержит каждую пару A < B, у которой в полном DFG есть оба ребра A→B и B→A, и частоты этих рёбер. Они могут возникать в разных случаях: наличие графового цикла не доказывает наблюдения A→B→A. Перечисление более длинных циклов не выполняется.
* `observed_aba.csv` содержит точные подряд идущие тройки A→B→A в отсортированной трассе при A ≠ B: ориентации A→B→A и B→A→B считаются отдельно; перекрывающиеся окна считаются отдельно (A,B,A,B,A даёт два A→B→A и одно B→A→B). `occurrences` — число окон, `case_count` — число различных случаев с данным окном; общий `cases_with_observed_aba` — объединение, не сумма строк. Поля с `equal_timestamp` считают окна и случаи, где хотя бы одна из двух соседних пар имеет равное время. Эти окна отражают порядок файла при равных метках, а не доказанный временной порядок. Случаи могут учитываться в нескольких строках; ни циклы, ни повторы сами по себе не ошибки.
* Без эталонного процесса отклонения — только статистические признаки: редкий вариант ровно с одним случаем, случаи строго выше общего P95. Они не означают нарушение; повторные лабораторные действия могут быть клинически необходимы.
* «Оптимальный» вариант — наблюдавшаяся точная последовательность с минимум 5 случаями и минимальной медианой длительности **отдельно для каждого последнего события**. При равных медианах выбирается большая частота, далее лексикографическая последовательность. Для конечного события без подходящего варианта выбор не делается. Самый частый вариант также показан отдельно. Последнее событие не обязательно означает завершение лечения; усечение лога, разная тяжесть и состав пациентов исключают вывод о клинической оптимальности или прямой эффективности маршрута.

## Файлы результатов

Проверенный запуск: `outputs/final/`. Содержит `summary.json` (качество, показатели, топ-5, выбор маршрутов), `activities.csv`, `transitions.csv`, `cases.csv`, `variants.csv`, `graph_two_node_cycles.csv`, `observed_aba.csv`, `dfg_full.html`, `dfg_filtered.png`, `case_duration_ecdf.png`. CSV в UTF-8 с BOM; списки событий/вариантов в ячейках — JSON. Все таблицы полные; интервалы в часах, временные метки UTC. В `cases.csv` и JSON для каждого случая сохранены последние пять событий и максимальный соседний интервал с его границами. В `transitions.csv` показаны число переходов, число разных случаев, медиана, P95 и сумма интервалов. В `activities.csv` — случаи с повтором каждого действия. `variants.csv` содержит полные последовательности, ID, частоты и длительности.

1 050 случаев; 15 214 событий; 16 действий; 14 164 перехода, 115 различных пар; 846 вариантов. Пропусков по перечисленным правилам нет, переупорядоченных случаев нет; 4 447 соседних пар имеют одинаковое время. Медианная длительность 128,24125 ч (5,34339 дня), P95 3 931,5585 ч (163,81494 дня); строго выше P95 — 53 случая. 784 варианта единичны; повторы действий встречаются в 744 случаях, самопереходов 1 034.

В полном DFG найдены 40 двухвершинных циклов; для 24 пар ни одна ориентация A→B→A не встречается подряд в отсортированных трассах. Наблюдаются 22 ориентированных типа A→B→A: всего 1 324 окна в 390 различных случаях (37,14% всех случаев), из них 1 112 окон (83,99%) содержат совпадение времени, поэтому реальный порядок в них не установлен. Наиболее часты Leucocytes→CRP→Leucocytes: 484 окна в 252 случаях, из них 461 окно с равными метками; CRP→Leucocytes→CRP: 478 окон в 255 случаях, из них 460 с равными метками. Эти числа описывают журнал и не являются признаком ошибки.

Сопоставление `outputs/initial` и `outputs/final`: все ранее сохранённые поля summary совпали; `activities.csv`, `transitions.csv`, `cases.csv`, `variants.csv`, `dfg_full.html` совпали побайтно. Суммы: 15 214 событий по действиям, 14 164 перехода и 1 050 случаев по вариантам. Подсчёт окон отдельно проверен по загруженным трассам. Полный набор из 9 тестов прошёл на указанном окружении.

Наиболее частый вариант `V0001`: ER Registration → ER Triage → ER Sepsis Triage, 35 случаев, медиана 0,28972 ч, последнее событие ER Sepsis Triage. Для Release A самый быстрый по определённой метрике вариант `V0011` (5 случаев), медиана 76,13583 ч. Другие конечные события и последовательности — в summary.json. Это сравнение описательное, не назначение лечения.

Среди переходов с частотой ≥30 наибольшая медиана у Release A → Return ER: 1 134,40056 ч, 276 переходов, P95 6 235,07701 ч. Этот интервал включает время после выписки до следующего появления и не равен ожиданию в больнице; отдельно Admission NC → Release A: медиана 67,74111 ч, 117 переходов. Самопереходы: Leucocytes 458, CRP 317, Admission NC 175, LacticAcid 83, Admission IC 1. Частые повторы в случаях: CRP 692, Leucocytes 677, Admission NC 313.

Все пять самых длительных случаев заканчиваются Return ER, и их максимальный интервал — Release A → Return ER: HG 10 135,77472 ч (интервал 10 014,255 ч); VAA 10 123,77972 ч (9 958,00417 ч); ZS 9 574,1675 ч (9 528,14833 ч); LS 9 527,24167 ч (9 460,65722 ч); UBA 9 287,27778 ч (8 928,24861 ч). Последние пять событий, границы и полные последовательности каждого указаны в summary.json. Их сравнение с общей медианой/P95 нужно читать с учётом того, что включён длительный период после выписки: это не длительность одной госпитализации.

Практические гипотезы для последующей проверки владельцем процесса: отдельно измерять эпизод до выписки и последующее возвращение; стратифицировать сравнение по конечному событию, группе пациентов и доступному контексту; проверить распределения интервалов и качество временных меток с сотрудниками; исследовать причины и ресурсы при длительных переходах без предположения, что любое повторное обследование избыточно. Эти шаги не являются клиническими рекомендациями.
